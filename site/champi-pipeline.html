TABPFN + VECTOR RESIDUAL FEEDBACK

Condition on features and an error-history vector.

z(t,h) = [X*(t,h), R(t,h)]
Δ̂(t,h) = g(z(t,h))
ŷ(t,h) = Expₓₜ(ûbase(t,h) + Δ̂(t,h))

X* contains the issue-time features and Base displacement. Each mature residual is a two-component east–north error vector. R stacks the latest four same-storm, same-lead residuals, transported to the current frame, with their ages and availability masks.

During historical fitting, the target residual is observed truth minus the Base forecast. At prediction time, the target truth is unknown: only residuals whose verification times have already passed enter R. The implementation uses two regression heads for the correction vector and calibrates position uncertainty separately.

CV = CONSTANT VELOCITY

Predict the departure from a moving reference.

CV is a motion representation, not cross-validation. In the current issue-centred east–north tangent plane, the last 6-hour displacement supplies the reference velocity v. For lead h:

b(h) = h · v
z(h) = Logxₜ(xₜ₊ₕ) − b(h)
x̂Base(h) = Expxₜ(b(h) + TabPFN(features, h))

Here Log and Exp are spherical maps; historical displacements are aligned to the current tangent plane. C0 learns the remaining truth-minus-Base displacement. C1 additionally receives four same-storm, same-lead residuals whose targets have already matured, with their ages and availability masks. Parallel transport aligns their coordinate frames.

TabPFN-3.5 uses frozen weights, 1,020 historical Base context rows and 320 residual-fit rows. CPU inference uses seed 42, one estimator and median outputs. F2 was selected on 2017, not on CHAMPI. This is pretrained inference with labelled historical contexts, not prediction without any labels.

Horizon-specific rolling calibration uses the most recent 100 mature scores after a 2019 warm-up. The rank is ceil((n + 1)(1 − α)). Live outputs are spherical position circles at 80%, 90% and 95%; retrospective ellipse experiments use a separate protocol. No environmental steering or regime gate is active.

Publication & verification

  1. Check sourcesThe Mac checks after each run and a 15-minute wait. Cloud source checks are scheduled twice hourly.
  2. Run or reuseA changed B-deck triggers actual Base/C0/C1 inference. Identical input preserves the original model generation time.
  3. PublishOnly validated public JSON reaches the data branch; GitHub Actions deploys Pages. Weights, contexts and the deployment private key remain local.
  4. VerifyThe browser reads the feed every minute. Public confirmation must precede the target; the first subsequently retrieved UCAR fix is frozen for scoring.

Retrieval time, model issue, generation time, forecast valid time and truth arrival are separate. Deployment queues, source schedules and Mac sleep affect latency. The last successful version remains visible with its actual timestamps.

How to interpret the C1 coverage gap

The absolute gap is |empirical coverage − target|, in percentage points. A 94.67% coverage rate at a 90% target has a 4.67 pp gap; it is not a 4.67 km track error. Above-target coverage may cost area, but does not by itself violate a lower-bound coverage objective. Point skill, undercoverage, issued area and coverage-matched area remain separate metrics.

The present CV-F2 C1 branch uses frozen 2016 residual contexts and rolling-rank calibration. The original short-horizon TabPFN-TS + PI+ protocol is a different experiment. A positive residual signal must be learned; C1 is not guaranteed to beat Base or C0 for every storm or horizon.
